# AppBridge

العربية · **[English](README.md)**

‏AppBridge تطبيق سطح مكتب لويندوز ينسخ تطبيق أو لعبة أندرويد — **ملفات APK وأجزاء split APK وملفات
OBB وموارد اللعبة المحمّلة في `Android/data`** — من هاتف إلى حاسوبك، ثم يثبتها على هاتف آخر أو عدة
هواتف عبر USB، فلا يضطر أصدقاؤك لتنزيل لعبة حجمها عدة غيغابايت من جديد. المثال الرئيسي: فري فاير
(`com.dts.freefireth`).

- يعمل **بدون إنترنت بالكامل**. لا حسابات ولا تحليلات، ولا يخرج أي شيء من حاسوبك.
- **عبر USB فقط** باستخدام أداة `adb` الرسمية من Google (مضمّنة داخل التطبيق، لا حاجة لتثبيت شيء).
- واجهة عربية وإنجليزية مع تبديل فوري ودعم كامل للاتجاه من اليمين لليسار، ووضع فاتح وداكن.

> **للاستخدام الشخصي.** شارك فقط التطبيقات التي يحق لك مشاركتها. ينسخ AppBridge التطبيقات كما هي
> تمامًا: لا يعدّل ملفات APK ولا يعيد توقيعها ولا يكسر حمايتها ولا يتجاوز أي فحص ترخيص.

## التنزيل والتثبيت

نزّل أحدث إصدار من صفحة **[Releases](https://github.com/yswef/AppBridge/releases)**:

- ملف `AppBridge-x.y.z-setup.exe` — مثبّت (لا يحتاج صلاحيات مدير، ويضيف اختصارًا في قائمة ابدأ
  ويتيح فتح ملفات `.appbridge` بنقرة مزدوجة)، أو
- ملف `AppBridge-x.y.z-win64-portable.zip` — فك الضغط في أي مكان وشغّل `AppBridge.exe`. غيّر اسم
  `portable.txt.example` إلى `portable.txt` لتبقى الإعدادات والسجلات والمكتبة بجانب التطبيق.

المتطلبات: ويندوز 10/11 بنظام 64 بت مع **WebView2 Runtime** من مايكروسوفت (موجود مسبقًا في ويندوز 11
وفي ويندوز 10 المحدَّث، وإلا [فثبّته من هنا](https://go.microsoft.com/fwlink/p/?LinkId=2124703)).

### تحذير Windows SmartScreen

ملفات البناء **غير موقّعة رقميًا** (شهادة التوقيع مدفوعة)، لذا قد يظهر عند أول تشغيل تحذير
«Windows protected your PC». اضغط **More info** (مزيد من المعلومات) ثم **Run anyway** (التشغيل على
أي حال). يمكنك مقارنة بصمة SHA-256 للملف مع الملف `SHA256SUMS.txt` في صفحة الإصدار، أو بناء التطبيق
بنفسك من المصدر (أدناه).

## طريقة الاستخدام

1. **فعّل تصحيح USB** على الهاتف: *الإعدادات ← حول الهاتف ←* اضغط *رقم الإصدار* 7 مرات، ثم
   *الإعدادات ← النظام ← خيارات المطوّر ← تصحيح USB*. في شاومي/أوبو/فيفو فعّل أيضًا *التثبيت عبر
   USB*. (يوجد دليل مصوّر داخل التطبيق: *الأجهزة ← كيف أفعّل تصحيح USB*.)
2. **وصّل الهاتف الأول** بكابل USB يدعم نقل البيانات. سيظهر في صفحة *الأجهزة* مع الطراز وإصدار
   أندرويد والمساحة الفارغة. إذا ظهرت حالة *بانتظار التصريح* فافتح قفل الهاتف واضغط **سماح** في نافذة
   «السماح بتصحيح USB؟» (مع تفعيل «السماح دائمًا»).
3. افتح **تطبيقات الهاتف**، واختر الفلتر *الألعاب* أو *تطبيقات المستخدم* أو *الكل*، ثم اختر اللعبة
   واضغط **استخراج إلى المكتبة**. يمكنك اختيار تضمين OBB و`Android/data` أو لا.
4. تابع التقدم في صفحة **المهام** (البايتات والسرعة والوقت المتبقي). يمكنك الإيقاف المؤقت والاستئناف،
   وإذا انفصل الكابل تنتظر المهمة عودة الهاتف نفسه وتكمل **دون إعادة نسخ الملفات المكتملة**.
5. **افصل الهاتف الأول ووصّل الهاتف الآخر** — واحدًا تلو الآخر أو عدة هواتف معًا عبر موزّع USB.
6. في **المكتبة** اضغط **تثبيت**، واختر الهواتف وراجع الفحوصات (الإصدار، التوقيع، المساحة…). يُثبَّت
   التطبيق على كل هاتف بالتوازي، وفشل هاتف لا يوقف الباقي.

### المشاركة مع صديق لديه حاسوبه الخاص

*المكتبة ← تصدير حزمة* ينشئ ملفًا واحدًا بامتداد `.appbridge` (ويمكن تقسيمه إلى أجزاء مثل
`.appbridge.001` و`.002` بحجم 2 غيغابايت لكل جزء — يُضبط الحجم من *الإعدادات*). يفتحه صديقك من
*المكتبة ← استيراد حزمة* (أو بنقرة مزدوجة بعد تثبيت AppBridge). تحتوي الحزمة أيضًا على ملف
`Install.bat` يعمل بوجود `adb.exe` فقط: غيّر امتداد الحزمة إلى `.zip` وفك ضغطها، وضع `adb.exe` بجانب
`Install.bat` ثم شغّله.

## ما الذي يُنسخ — والقيود

| يُنسخ | لا يُنسخ |
| --- | --- |
| كل ملفات APK (عبر `pm path`: الأساسي وأجزاء split) | بيانات التطبيق الداخلية `/data/data/<package>` (تسجيل الدخول والتقدم المحفوظ) — مستحيل بدون روت |
| `/sdcard/Android/obb/<package>` | بيانات التطبيقات الأخرى والحسابات |
| `/sdcard/Android/data/<package>` (الموارد المحمّلة) | |

- يبدأ التطبيق المنسوخ **من جديد** على الهاتف الآخر (سجّل الدخول مرة أخرى). وقد ترفض الألعاب
  الأونلاين العمل إذا كان **الخادم يطلب إصدارًا أحدث** أو يتحقق من الحساب أو الجهاز.
- **أندرويد 14 و`Android/data`**: معظم الهواتف تسمح لـ ADB بقراءة هذا المجلد والكتابة فيه، لكن بعض
  الشركات تمنعه. عندها يخبرك AppBridge بوضوح ويعرض المتابعة بدونه (وستعيد اللعبة تنزيل مواردها). وعند
  التثبيت، إذا رفض الهاتف الكتابة هناك، يفتح AppBridge اللعبة مرة واحدة لينشئ أندرويد المجلد ثم يعيد
  المحاولة.
- يمنع أندرويد 14 التطبيقات المبنية لإصدارات أندرويد قديمة جدًا؛ يعيد AppBridge المحاولة تلقائيًا مع
  الخيار `--bypass-low-target-sdk-block`.
- تثبيت إصدار **أقدم** فوق إصدار أحدث، أو تطبيق بتوقيع مختلف عن المثبت، يتطلب إزالة المثبت أولًا
  (وتُفقد بياناته المحلية على ذلك الهاتف). يسألك AppBridge قبل فعل ذلك.
- يجب أن يتوافق الكود الأصلي مع معالج الهاتف (مثلًا من هاتف `arm64` إلى هاتف `arm64`).
- بعض الهواتف تحتاج تعريف USB من الشركة المصنعة على ويندوز (مثل *Samsung USB Driver*).

## فحوصات السلامة

- تُسجَّل بصمة SHA-256 لكل ملف عند الاستخراج (في `manifest.json`) ويتم التحقق منها قبل التثبيت (يمكن
  إيقاف ذلك من *الإعدادات*) أو عند الطلب (*المكتبة ← فحص السلامة*).
- تُقرأ شهادات التوقيع من كتلة توقيع APK بنظام v2/v3 (وv1 كبديل)؛ ويجب أن تحمل كل أجزاء split الشهادة
  نفسها، وتُقارن الشهادة بالتطبيق المثبت على الهاتف الهدف.
- يُقارن `versionCode` المثبت (تحذير عند التثبيت على إصدار أحدث)، إضافة إلى الحد الأدنى لإصدار أندرويد
  ومعمارية المعالج والمساحة الفارغة.

## أين تُحفظ الملفات

- المكتبة: افتراضيًا `Documents\AppBridge Library` (يمكن تغييرها من *الإعدادات*). لكل تطبيق مجلد يحتوي
  `manifest.json` و`icon.png` و`apk\` و`obb\` و`data\`؛ ويُعاد بناء فهرس SQLite ‏(`library.db`) من
  المجلدات، لذا يمكن نقل المكتبة أو نسخها.
- الإعدادات والسجلات: `%LOCALAPPDATA%\AppBridge`. زر *الإعدادات ← تصدير السجلات* يضغط السجلات إن احتجت
  للمساعدة.
- نصيحة: اختر مسار مكتبة قصيرًا (مثل `D:\AppBridge`) — بعض الألعاب لها مجلدات بيانات عميقة جدًا.

## البناء من المصدر

المتطلبات: Python 3.11 أو أحدث، وNode.js 20 أو أحدث، وويندوز للبناء النهائي.

</div>

```bash
cd frontend && npm ci && npm run build && cd ..
python tools/fetch_platform_tools.py
pip install -e ".[dev]"
python backend/main.py
pyinstaller packaging/appbridge.spec --noconfirm
iscc /DMyAppVersion=0.1.0 packaging\installer.iss
```

<div dir="rtl">

الاختبارات وفحص الأنماط: `pytest -q` و`ruff check backend tools`. تستخدم الاختبارات مخرجات `adb`
مسجلة وجهازًا وهميًا (مجلد يحاكي الهاتف).

### الإصدارات

يشغّل GitHub Actions الاختبارات وفحص الأنماط عند كل push، ويبني تطبيق ويندوز (PyInstaller بنمط onedir
مع ملف zip ومثبّت Inno Setup)، وعند إنشاء tag مثل `v0.1.0` يُنشئ GitHub Release تلقائيًا ويرفق الملفات:

</div>

```bash
git tag v0.1.0 && git push origin v0.1.0
```
